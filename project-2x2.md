Система прогнозирования лотереи "2x2" (4 числа из 26, две пары). Расположена на сервере `ssh root@45.146.164.144` по пути `/root/projects/2x2/`. Текущая версия: v7.0.0.

**Архитектура:** Несколько анализаторов генерируют анти-кандидатов (числа для исключения), затем селектор формирует финальный прогноз.

**Анализаторы:**
- `triple_beam_analyzer.py` — ретро-анализ по 3 лучам (V, DL, DR), ищет совпадения хвостов блоков + суммы
- `trigger_analyzer.py` — паттерны из 3 позиций → AC из следующего тиража
- `morse_analyzer.py` — чёт/нечёт кодирование, поиск повторяющихся паттернов (выключен в конфиге)
- `rarity_index.py` (v2) — метод наложения распределений из видео Пикюрики

**Селектор:** `horizontal_selector_v4.py` — получает AC, применяет температурный фильтр + Rarity Index (на уровне комбинации), генерирует прогноз с валидацией.

**Ключевые концепции:** 4 позиции (каналы A, B, C, D), анти-кандидаты, темперура чисел, Rarity Index.

## Rarity Index v3 — ДЕПЛОЙНУТ (2026-05-22)

**Алгоритм (метод наложения распределений, из видео Пикюрики):**
1. Упорядочить числа по возрастанию → N независимых каналов
2. Построить распределение частот для каждого канала (ось X = числа, ось Y = частота)
3. Нормализовать к макс=1000
4. Разделить на 5 категорий по рангу частоты → коды: 0, ±1, ±2
5. Знак: число < пикового → отрицательный, число > пикового → положительный
6. RI комбинации = |сумма кодов|

**v3 — поле-ориентированная структура (2026-05-22):**
- 2 независимых игровых поля, по 2 канала в каждом:
  - Поле 1: A1=min(n1,n2), B1=max(n1,n2)
  - Поле 2: A2=min(n3,n4), B2=max(n3,n4)
- RI_поле = |code_A + code_B|
- **Финальный RI = max(RI_поле1, RI_поле2)** — берём «худшее» поле
- Диапазон RI: 0-4 (вместо 0-8 при старой структуре)
- Причина: min и max в одном поле коррелированы (min ≤ max), поэтому RI_поле ≤ 2 на практике

**Распределение RI (depth=24806):** RI=0: 12.4%, RI=1: 44.4%, RI=2: 43.1%, RI=3+: 0%
