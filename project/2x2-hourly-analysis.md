## Анализ успешных прогнозов по часам (2026-05-29)

Проведён анализ 12,676 прогнозов с валидным временем (01.02.2026 — 31.03.2026). 12,822 записи пропущены (нет даты/времени —早期 период парсера).

**Общий %命中 (1+ число):** 46.7% (5,917 / 12,676)

**Лучшие часы:**
- 11:00 — 49.8% (265/532)
- 14:00 — 49.4% (267/540)
- 15:00 — 48.6% (261/537)
- 21:00 — 48.4% (242/500)
- 10:00 — 48.3% (259/536)

**Худшие часы:**
- 13:00 — 41.8% (223/534)
- 08:00 — 42.7% (229/536)
- 16:00 — 44.0% (211/480)
- 02:00 — 44.8% (235/524)

**Разброс:** 8 п.п. между лучшим (11:00 = 49.8%) и худшим (13:00 = 41.8%) часом.

**Примечание:** Данные без пропусков в нумерации draws (нет разрывов). Два формата дат: старый "DD.MM.YYYY HH:MM:SS" в draw_date, новый — draw_date + draw_time раздельно.

**Why:** User хотел выявить временные паттерны успешных прогнозов для потенциальной оптимизации стратегии.

**How to apply:** При дальнейшем анализе эффективности или настройке стратегии — учитывать что утренние и дневные часы (10-15) показывают лучшие результаты, чем вечерние и ночные.

   - Пересчитывать статистику в каждом цикле
   - Выдавать сигнал для принятия решения о вступлении в игру (лучшее временное окно)
   - Интегрироваться в пайплайн анализаторов наравне с trigger, beam и др.

## Реализация (2026-05-29)

**Файлы:**
- `/root/projects/2x2/hourly_timing_analyzer.py` — новый анализатор (HourlyTimingAnalyzer)
- `/root/projects/2x2/dashboard_2x2.py` — баннер + подсветка строк + API endpoints
- `/root/projects/2x2/driver_v5.py` — вызов timing analyzer после каждого цикла
- `/root/projects/2x2/config_v5.yaml` — секция hourly_timing

**Таблица:** `hourly_timing_stats` — hour, day_of_week, window_days (7/30/90/0), hit_rate, max_fail_streak, avg_matches

**API endpoints:**
- `/api/timing_signal` — JSON: action (PLAY/WAIT), current_score, best_hours[], next_favorable{}
- `/api/favorable_draws` — set of draw_number для подсветки в таблице

**Визуализация на дашборде:**
- Зелёный баннер PLAY / жёлтый WAIT над таблицей прогнозов
- Строки благоприятных тиражей — зелёная левая рамка
- Best hours и next favorable час с минутами

**Score formula:** base = 30d hit_rate для hour+dow (fallback на all-time) + trend adjustment (7d vs 30d * 0.3) + streak bonus (mean reversion). Порог PLAY = 0.47.

**Известные особенности:**
- All-time данные показывают 75-81% hit_rate для отдельных hour+dow (маленькая выборка 76-80 записей)
- 30d window: hour+dow имеет 10-21 записей, поэтому используется min_predictions=10 для 30d
- Dashboard работает на порту 5000 (systemd: 2x2-dashboard.service, venv: /root/venvs/2x2/)

## Архитектурные находки для интеграции (2026-05-29)

**Интерфейс анализаторов:** Нет формального базового класса. Де-факто стандарт — метод `analyze(draws)` → `Dict[int, List[Tuple[int, str, str]]]` (позиция → список (число, причина, хеш_триггера)). Только TriggerAnalyzer и DiagonalTriggerAnalyzer следуют этому чисто. Остальные читают БД сами.

**Как добавить новый анализатор:** Жёстко прописывается в `driver_v5.py` (класс `DriverV6`). Нет динамической регистрации. Нужно редактировать `run_analysis()`.

**Наш analyzer будет отличаться:** Он не производит anti-candidates, а даёт timing signal — рекомендацию когда входить в игру. Это новый тип анализатора в системе.

**Данные для таблицы hour_stats:**
- `draws` (25,498 записей) + `predictions_v4` (25,498 записей) — JOIN по draw_number
- 12,676 записей с валидным временем, 12,822 без (早期 период)
- Форматы дат: старый "DD.MM.YYYY HH:MM:SS" в draw_date, новый — draw_date + draw_time раздельно
