### Предполагаемая задача (в разработе, 2026-06-07):

Пользователь хочет выполнить **обратный инжиринг** для корреляции:
- Число итераций до успеха
- Температура прогноза
- RI комбинации
- **Точность прогноза** (угадано 1/2/3/4 числа из actual_*)

**Цель:** Оптимизировать число итераций Селектора через анализ исторических данных с известными результатами.

**Метод:** 
1. Запустить Селектор заново на исторических данных (с known actual_*)
2. Записать реальные `attempts` для каждого тиража
3. Скоррелировать с успехом прогноза (hit rate)
4. Найти "sweet spot" для адаптивного управления итерациями

**Why:** Современные данные накапливают только `attempts` из реального выполнения driver (98% = 1 итерация, без вариаций). Нужно исследование для понимания, даёт ли увеличение итераций улучшение точности прогнозов.
**How to apply:** При разработке Iteration Tuner — использовать полный pipeline (Triple Beam → Selector), не упрощать до random selection. Хранить `attempts` в predictions_v4.attempts + приложить metadata (combo RI, temp features).
