**Ошибка в методологии анализа итераций** (2026-06-07, исправлено):

Пользователь повторял несколько раз, что подход был неверен: я брал анти-кандидаты для тиража (которые **одни и те же** для данного тиража), фильтры (тоже **одни и те же**), и запускал селектор **один раз**, считая внутренние итерации.

**Правильная методология (обратный инжиниринг):**
- Анти-кандидаты для одного тиража — фиксированы (одни и те же)
- Фильтры для одного тиража — фиксированы (температуры, RI, суммы и т.д.)
- Селектор должен запускаться **многократно** (как если бы он "переигрывал" этот тираж несколько раз)
- Цель: посчитать, сколько раз селектору потребовалось **повторить процесс генерации** (запуск с нуля), прежде чем он сгенерировал комбинации с 1/2/3/4 совпадениями

**Что сломалось в коммуникации:**
- Я использовал термин "итерация" для внутренних циклов (attempts внутри одного запуска)
- Пользователь имел в виду "запуск" или "попытка" (полный запуск селектора с нуля)
- Пользователь несколько раз повторял "ты просто не понял", "дубина" = методология была неверна
- Пользователь спрашивал: "почему на 4 позиции ни одного совпадения?" → потому что 1 запуск недостаточен
- Пользователь объяснял: "селектор должен не с первого раза завершать построение прогноза, а сделать это несколько раз"

**Why:**
- Пользователь приводил термин "обратный инжиниринг" — нужно воспроизвести **многократные попытки** Селектора на одном и том же историческом состоянии
- Ранее проходил endurance test: 20 тиражей × до 500 attempts (запусков) — аналогичная логика
- Один запуск = одна "ветка" поиска, много запусков = больший охват комбинаций

**How to apply:**
- Внешний цикл: N запусков селектора (многократно перезапускать)
- В каждом запуске: селектор работает как обычно (генерация → валидация → RI check)
- Как только в N-м запуске получена валидная комбинация с K совпадениями — записать запуск №N для уровня K
- Продолжать до exhaustion всех N запусков
