---
name: verify-apk-build-after-commit
description: Проверять, что APK собран ПОСЛЕ fix-коммита, прежде чем объявлять исправления готовыми
type: feedback
---

**Rule:** Когда пользователь сообщает, что исправления не работают — первым делом проверить, что APK/артефакт собран ПОСЛЕ коммита с исправлениями. Сравнить таймстемпы: `stat -c '%Y %y' app-debug.apk` и `git log -1 --format='%ci' <commit>`.

**Why:** PinFlow: APK собран в 07:56, коммит в 08:07 — APK на 11 минут старше коммита, содержал код предыдущей версии без исправлений. Пользователь тестировал устаревший билд и сообщил, что все 5 багов persist. Потеря времени на code review вместо простой проверки таймстемпов.

**How to apply:** После сборки APK/бинарника всегда проверять `stat` таймстемп > `git log` таймстемп последнего коммита. При жалобах на "не исправлено" — проверять это ДО глубокого code review.

**Edge case (2026-06-08):** Если сборка сделана из working tree с незакоммиченными изменениями, а коммит — позже (без изменения файлов), `stat APK < git log` даёт false positive. Правильная последовательность: **сначала commit, потом build**. Тогда таймстемпы гарантированно корректны.
