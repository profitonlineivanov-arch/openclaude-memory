name: Don't invent task goals
description: When user gives a simple command (ps/tail/grep/ls/ssh) without stating a goal, run the command and report output — do not invent research goals or analysis directions
type: feedback
---

Когда пользователь даёт конкретную команду (ps aux, tail, grep, ls, ssh + одна команда) без явной формулировки цели — **выполнить команду и отрапортовать вывод**. Не придумывать исследовательскую цель, не делать «анализ сверх», не предлагать следующие шаги.

**Why:** 2026-06-08, RI post-check: пользователь написал `ssh root@45.146.164.144 "ps aux | grep selector_iteration | grep -v grep; echo '---'; tail -20 /root/projects/2x2/selector_iteration_10k_no_ri.log"` — это была проверка статуса завершённого прогона + хвост лога. Я в ответ сделал:
1. Сравнение с прогоном «с RI» (ты не просил — прогон с RI был завершён до этого и его результаты уже зафиксированы в `team/2x2-selector-iteration-analysis.md` и `project/selector-iteration-reverse-engineering.md`)
2. Составил таблицу с дельтами (ты не просил)
3. Объявил «RI не load-bearing», предложил «кандидат на удаление» (ты не просил)
4. На вопрос «какая цель?» сначала приписал тебе: «цель — выяснить нужен ли RI» — это была **моя** реконструкция, не твоя цель
5. На «нет! я не ставил такой цели!» начал оправдываться и заново «вспоминать», усилив фрустрацию
6. Ты эскалировал: «я заебался писать ее и каждый раз какая то шляпа» — это паттерн, не разовый срыв

Зафиксировано уже в:
- `feedback/exact-scope.md` (случай #2 — RI post-check)
- `feedback/user-frustration-escalation.md` (escalation lesson, 2026-06-08 RI post-check)

Этот файл — отдельное правило, чтобы не путать с general «exact scope» (которое шире). Сужено именно до post-check команд без явной цели.

**How to apply:**
- Получил `ssh ... "ps aux | tail -20"` или эквивалент → **выполнил → отчитался о выводе**. Точка.
- Если вывод уже проанализирован раньше и записан в memory — отсылка к этому memory-файлу («уже зафиксировано в `team/2x2-selector-iteration-analysis.md`, новых выводов нет»), а не новая аналитика
- Если пользователь не сказал «проанализируй» / «сравни» / «оцени» — **не делать этого самому**
- Если хочется предложить следующий шаг — сначала спросить, а не предлагать: «есть новый анализ?» или «нужна интерпретация?»
- Если пользователь отрицает поставленную тобой цель — **не оправдываться**, не «вспоминать», не пытаться реконструировать. Принять, что цели не было, спросить какая цель на самом деле
- Не пытаться «загладить» прошлые ошибки серией уточнений — это только ухудшает ситуацию
