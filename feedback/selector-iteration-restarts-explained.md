**Критическое пояснение методологии анализа итераций** (2026-06-07):

Пользователь несколько раз объяснял, что анализ был проведен **НЕВЕРО**:

**Что я делал неправильно:**
- Брал анти-кандидаты для тиража (фиксированы, одни и те же)
- Брал фильтры для тиража (фиксированы, одни и те же)
- Запускал селектор **один раз** и считал "внутренние итерации" внутри этого запуска
- Как только находил валидную комбинацию — немедленно возвращал результат

**Правильная методология:**
- Анти-кандидаты для одного тиража — **ОДНИ И ТЕ ЖЕ** (не меняются)
- Фильтры для одного тиража — **ОДНИ И ТЕ ЖЕ** (температуры, RI, суммы固定)
- Селектор должен запускаться **многократно** (как если бы "переигрывал" тот тираж много раз)
- В **каждом запуске** селектор работаетNormalьно: генерация → валидация → RI check → возвращает первую валидную комбинацию
- Нужно посчитать: **на каком номере запуска** (1-й, 2-й, 3-й... N-й) впервые получили комбинацию с 1/2/3/4 совпадениями

**Пример:**
- Запуск №1 → валидная комбинация → 0 совпадений с реальным тиражом
- Запуск №2 → валидная комбинация → 0 совпадений
- Запуск №3 → валидная комбинация → **1 совпадение** ⇒ `iter_match1 = 3`
- Запуск №4 → валидная комбинация → 0 совпадений
- Запуск №5 → валидная комбинация → **2 совпадения** ⇒ `iter_match2 = 5`
- ...
- Запуск №42 → валидная комбинация → **4 совпадения** ⇒ `iter_match4 = 42`

**Итог:**
- `iter_match1 = 3` — нужно **3 запуска** селектора, чтобы в первый раз получить хоть 1 совпадение
- `iter_match2 = 5` — нужно **5 запусков**, чтобы в первый раз получить 2 совпадения
- `iter_match3 = 15` — нужно **15 запусков**, чтобы в первый раз получить 3 совпадения
- `iter_match4 = 42` — нужно **42 запуска**, чтобы получить 4 совпадения

**Ключевое отличие:** не "итерация внутри цикла", а "номер полного запуска селектора".

**How to apply:**
- Внешний цикл: `for run in range(1, max_runs + 1)` (например, 1000 запусков)
- Внутри каждого запуска: обычный селектор (`generate_prediction()` → валидация → RI check)
- Как только получил валидную комбинацию → посчитать matches с реальным тиражом
- Если matches ≥ K и `iter_matchK` еще не установлен → установить `iter_matchK = run`
- После exhaustion всех запусков вернуть лучшую найденную комбинацию + полную историю `iter_match1/2/3/4`
